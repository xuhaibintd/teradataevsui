文書群 ID：`TD-EVSUI-DD`

言語：日本語のみ

状態：内部規範文書
対象：開発者、レビュー担当者、テスター、運用担当者、AI コーディングエージェント

## 1. 目的

このディレクトリは、teradataevsui の実装を安全に理解、変更、試験、運用するための詳細設計の正本である。README は利用方法、`docs/` は公開説明を担い、本ディレクトリはコード変更に必要な内部契約を扱う。

設計書は現在のコード、SQLite マイグレーション、固定された依存関係、およびテストを根拠とする。実装と設計が食い違う場合、変更担当者は差異を明示し、設計または実装を同じ変更単位で整合させる。

## 3. 読み方

変更前に `01_SYSTEM_ARCHITECTURE.md` と `02_MODULE_CATALOG.md` を読み、対象機能の設計書を読む。UI を含む場合は `13_UI_DESIGN.md` も必須とする。複数領域を横断する変更では、次の順に確認する。

1. 状態の所有者と永続化先
2. 認証、権限、シークレット境界
3. 外部 SDK とファイル I/O の境界
4. ワークフローと失敗時の補償
5. HTTP またはジョブの入出力
6. UI とメッセージ
7. テスト、運用、公開物

## 4. 共通規則

- `DD-COMMON-001`：ルーターは入力、認証、応答形式を担当し、業務処理を抱え込まない。
- `DD-COMMON-002`：外部 SDK 呼び出しはインテグレーション、サービス、またはワークフロー境界から行う。
- `DD-COMMON-003`：SQLite クエリはリポジトリまたは永続化ファサードに置く。
- `DD-COMMON-004`：ブラウザーセッション、SQLite、プロセス全体、Teradata、ファイルシステムの状態を混同しない。
- `DD-COMMON-005`：シークレットを通常 JSON、HTML、URL、ログ、ジョブ結果、テスト成果物へ含めない。
- `DD-COMMON-006`：外部処理は成功、部分成功、失敗、タイムアウト、中断、再実行を設計する。
- `DD-COMMON-007`：適用済みマイグレーションと永続マニフェストの意味を後から変更しない。
- `DD-COMMON-008`：最新版として固定した SDK の公開契約を使用し、推測した互換分岐を画面や業務層へ増やさない。
- `DD-COMMON-009`：新しい生成ファイルは成果物台帳へ登録し、保存期限と削除方法を定義する。
- `DD-COMMON-010`：設計変更には対応テストと本設計書群の更新を含める。

## 5. AI エージェントの必須手順

1. 対象モジュールをファイル名だけで判断せず、呼び出し元とテストを検索する。
2. 変更する公開関数、永続データ、HTTP 経路、ジョブ種別、ファイル形式を列挙する。
3. 対応する設計 ID を確認する。
4. 最小の一貫した変更を実装する。
5. 正常系と失敗系を検証し、関連しないユーザー変更を保持する。
6. 実装、設計、テスト、運用手順の差異を残さない。
