# teradataevsui UI 詳細設計書

文書 ID：`TD-EVSUI-UI-001`

言語：日本語のみ

状態：規範文書

対象：設計者、開発者、テスター、コードレビュー担当者、AI コーディングエージェント
最終更新日：2026-09-07

## 1. この文書の目的

本書は、teradataevsui の UI を一貫して設計、実装、変更、検証するための唯一の詳細設計基準である。画面の見た目だけではなく、情報構造、データの出所、操作のタイミング、メッセージの表示位置、エラー時の挙動、権限制御、応答性能、アクセシビリティ、および回帰テストまでを規定する。

本書の主な目的は次のとおりである。

1. 人が画面の役割と正しい操作を短時間で理解できるようにする。
2. AI コーディングエージェントが、局所的な修正によって別の画面や状態を壊さないようにする。
3. 同じ意味のナビゲーション、重複メッセージ、欠落した表見出し、意味のない空白、説明欄の一律ダッシュ表示など、過去に発生した UI 問題の再発を防止する。
4. UI、ルーター、ワークフロー、サービス、JavaScript、CSS、およびテストを一つの変更単位として扱う。

## 2. 規範語と優先順位

本書では次の語を規範語として使用する。

| 規範語 | 意味 |
|---|---|
| 必須 | 例外なく満たす。満たさない変更はマージ不可とする。 |
| 原則必須 | 明確な理由とレビュー記録がある場合だけ例外を認める。 |

## 3. 製品 UI の基本原則

### 3.1 必要な機能だけを明確に配置する

- `UI-PRINCIPLE-001`：各画面は一つの主要目的を持つこと。
- `UI-PRINCIPLE-002`：同じ機能への主要ナビゲーションを二重に配置しないこと。
- `UI-PRINCIPLE-003`：実際に利用しない Worker、API 世代、内部 SDK クラス、診断値を UI に露出しないこと。
- `UI-PRINCIPLE-004`：装飾目的だけのカード、巨大な余白、説明の重複、過剰なステップ表示を追加しないこと。
- `UI-PRINCIPLE-005`：利用者が次に行う操作を、見出し、状態、主要ボタンの順で判断できること。

### 3.2 設定と実行を分離する

- `System Configuration` は共有設定を管理する管理者専用画面である。
- ホーム画面の `Connect & Manage` は、定義済み接続の選択、接続、状態確認、および Vector Store 管理を行う実行画面である。
- ホーム画面に `Administration` という重複メニューを置かない。BookRAG 固有の管理は `BookRAG Governance` と呼ぶ。
- データベース接続情報、PAT、PEM、および Unstructured API キーをホーム画面で直接編集しない。

### 3.3 選択と実行を分離する

- 行、タブ、プルダウンの選択だけで、ネットワーク要求、Teradata 接続、Vector Store 初期化、削除、または長時間処理を開始してはならない。
- サーバー処理を開始する操作には、動詞を含む明示的なボタンを使用する。
- 選択状態は直ちに画面へ反映し、利用者を待たせない。

### 3.4 技術の世代差を画面へ持ち込まない

- UI は、プロジェクトで固定された最新版 `teradatagenai` の公開 API に合わせる。
- `V1 Vector Stores` と `V2 Collections` のような内部的または移行期の区分を通常画面へ併記しない。
- 利用者には一つの `Vector stores` 資源モデルとして提示する。
- API 差異が内部で必要な場合はアダプター層で吸収し、削除権限など利用者の判断に不可欠な差異だけを操作可否へ反映する。

## 4. 情報アーキテクチャ

### 4.1 全体構造

```text
共通ヘッダー
├─ Teradata ブランド
├─ グローバル操作メッセージ
└─ System Configuration / Log Out / ユーザー名

ホーム /
├─ Connect & Manage
├─ Vector Store Creation
├─ Vector Store Retrieval
└─ BookRAG Governance

System Configuration /admin/users
├─ Database Connections
├─ Unstructured IO
└─ User Management

初回設定 /setup（users が 0 件の場合だけ）
└─ Create administrator
```

### 4.2 画面責務

| 画面 | 主要目的 | 主要操作 | 表示対象 |
|---|---|---|---|
| `Connect & Manage` | 接続と Vector Store 運用 | 接続、切断、更新、選択、削除 | 接続概要、ヘルス、資源一覧 |
| `Vector Store Creation` | Vector Store の作成 | 文書選択、処理方式設定、ジョブ投入 | 入力設定、進捗、作成結果 |
| `Vector Store Retrieval` | 検索と検証 | Vector Store 選択、検索方式選択、質問送信 | 会話、検索結果、BookRAG エビデンス |
| `BookRAG Governance` | BookRAG 文書統制 | メタデータ、文書関係、JSON 検査 | BookRAG 対象文書と構造 |
| `System Configuration` | 共有システム設定 | 接続 CRUD、Unstructured 設定、ユーザー管理 | 暗号化済み設定とアカウント |

### 4.3 ロール別表示と操作

| 機能 | `admin` | `operator` | `viewer` |
|---|---:|---:|---:|
| 接続、切断、一覧更新、検索 | 可 | 可 | 可 |
| Vector Store 作成 | 可 | 可 | 不可 |
| 通常 Vector Store 削除 | 可 | 可 | 不可 |
| 管理者権限が必要な削除 | 可 | 不可 | 不可 |
| BookRAG メタデータの更新 | 可 | 可 | 参照のみ |
| `System Configuration` | 可 | 不可 | 不可 |
| ユーザー管理 | 可 | 不可 | 不可 |

権限制御は画面上の非表示または無効化だけに依存してはならない。サーバー側でも同じ権限を必ず検証する。

### 4.4 初回管理者設定

- `UI-SETUP-001`：ユーザーが 0 件の場合、未ログイン利用者を通常 login ではなく `/setup` へ自動誘導する。
- `UI-SETUP-002`：画面は `Create administrator`、短い説明、Username、Password、Confirm password、作成ボタンだけを持つ。
- `UI-SETUP-003`：password は 8 文字以上とし、確認不一致を含む入力エラーは同じフォームで明示する。password 値は再表示しない。
- `UI-SETUP-004`：作成成功後は login へ移動し、一件の短い成功メッセージを表示する。初回設定入口は直ちに無効になる。
- `UI-SETUP-005`：既存ユーザーがいる状態で `/setup` を開いても初期化フォームを表示せず、login へ戻す。
- `UI-SETUP-006`：初回設定と login はアプリケーション用 HTMX/JavaScript を読み込まず、通常の HTML form とブラウザー検証で動作する。

未認証画面は共通トップメッセージ領域を持たないため、この二画面の入力エラーと初回作成完了だけは認証パネル内へ一度だけ表示できる。

## 5. 共通レイアウト

### 5.1 共通ヘッダー

- `UI-LAYOUT-001`：デスクトップのヘッダー基準高は `88px` とする。
- `UI-LAYOUT-002`：ブランド領域、メッセージ領域、操作領域の 3 列とする。
- `UI-LAYOUT-003`：ブランドは Teradata ロゴと `Enterprise AI Platform` のみで構成する。ロゴ下に `teradataevsui` を表示しない。
- `UI-LAYOUT-004`：メッセージがない場合も、ヘッダーを不必要に高くしない。
- `UI-LAYOUT-005`：長いメッセージによって `System Configuration`、`Log Out`、ユーザー名が画面外へ押し出されてはならない。
- `UI-LAYOUT-006`：幅 `1100px` 以下では 1 列へ折り返し、高さは内容に合わせる。

### 5.2 ホーム画面

- デスクトップでは左ナビゲーションと右コンテンツの 2 列とする。
- 左ナビゲーションの幅は画面に応じて約 `210px` から `260px` とする。
- 有効なセクションは一つだけ表示する。
- 未接続時は接続が必要なメニューを無効化し、その理由を状態として伝える。
- ページ全体に固定高を設定して内容を切らない。必要なスクロールは、ページまたは意味のある一覧領域のどちらか一方へ与える。

### 5.3 余白と密度

- `UI-LAYOUT-010`：主要領域の間隔は共通トークン `--layout-gap` を使用する。
- `UI-LAYOUT-011`：情報量が少ないカードを画面高いっぱいまで引き延ばさない。
- `UI-LAYOUT-012`：エラー、成功、選択状態によって主要コンテナの幅と列構成を変えない。
- `UI-LAYOUT-013`：空状態には説明と次の操作だけを表示し、空の巨大パネルを残さない。
- `UI-LAYOUT-014`：表だけを狭い左側へ寄せ、右側を空白にするレイアウトを禁止する。表は利用可能幅を使う。

## 6. グローバル操作メッセージ

### 6.1 唯一の表示位置

- `UI-MESSAGE-001`：接続、保存、更新、削除、作成、読み込み、認証、および通信エラーの操作メッセージは、共通ヘッダー中央の `#top-op-stack-shell` に一度だけ表示する。
- `UI-MESSAGE-002`：同じ内容をヘッダーと操作パネルの両方へ表示してはならない。
- `UI-MESSAGE-003`：パネル内の過去メッセージを残したまま、新しいメッセージを上へ追加してはならない。最新の主要メッセージで置換する。
- `UI-MESSAGE-004`：サーバー応答は HTMX の OOB 更新、クライアント側の送信前・通信失敗は共通 `setTopMessage` 経由で更新する。

### 6.2 表示優先順位

同時に複数状態が存在する場合は、次の優先順位で一件だけ表示する。

1. エラー
2. 成功
3. 警告または注意
4. 接続状態

### 6.3 パネル内に残してよい情報

次は操作メッセージではなく、業務結果または継続状態なので該当パネル内へ表示してよい。

- チャットの質問、回答、検索結果、BookRAG エビデンス
- ジョブの進捗、処理件数、生成アーティファクト
- 入力欄単位の検証エラー
- ヘルスカードの現在値
- 空状態、説明文、警告詳細の展開領域

同じ成功または失敗文を、これらの領域とヘッダーへ重複表示してはならない。

### 6.4 エラー文

- 生のスタックトレース、PAT、パスワード、API キー、PEM 内容、セッション ID を表示しない。
- SDK の長いエラーは利用者向けに要約し、必要な場合だけ安全化した詳細を `title` または展開領域へ置く。
- 競合状態 `409` は、例として「現在作成・更新・削除処理中のため削除できません。完了後に更新してください」のように、原因と次の行動を示す。
- メッセージはヘッダーを破壊しない最大高と折り返しを持つ。

## 7. `Connect & Manage` 詳細設計

### 7.1 左側：接続

表示順は次のとおりとする。

1. `System connection` 見出し
2. 定義済み `Database connection` 選択
3. 選択中プロファイルの読み取り専用概要
4. `Connect` と `Disconnect`
5. 接続中の短い進捗

接続概要には `Connection`、`Host`、`Username`、`UES URL`、`Credentials`、`PEM file` を表示する。シークレット値は表示せず、`configured` または `not configured` の状態だけを表示する。

- 接続済みの間は接続プロファイルを変更不可とする。
- プロファイル変更には切断を要求する。
- `Connect` は未接続かつ必須設定がそろった場合だけ有効にする。
- `Disconnect` は接続中だけ有効にする。
- プルダウンを選択しただけで接続してはならない。

### 7.2 右側：管理概要

上から次の順に配置する。

1. `Vector stores` 見出しと説明
2. `Refresh management data`
3. `Connection`、`EVS health`、`Last checked` の概要カード
4. 必要な場合だけ警告詳細
5. `Available vector stores`、件数、フィルター
6. 選択バーと削除操作
7. Vector Store 表

`Refresh management data` は、接続済みの場合だけ有効にする。このボタンがヘルス、一覧、および一覧に必要な詳細情報を取得する明示的な境界である。

### 7.3 Vector Store 表

- `UI-TABLE-001`：表見出しはスクロール中も固定し、常に表示する。
- `UI-TABLE-002`：列数、見出し数、各行のセル数を必ず一致させる。
- `UI-TABLE-003`：表全体は利用可能幅を使い、必要な場合だけ表コンテナ内を横スクロールさせる。
- `UI-TABLE-004`：行選択後も表の高さ、列幅、見出し位置を変えない。

列は次の 6 列で固定する。

| 順序 | 見出し | 内容 | 空値表示 |
|---:|---|---|---|
| 1 | `Vector store name` | 正確な資源名 | 空値を許可しない |
| 2 | `Description` | 用途説明。BookRAG 判定も含む | 空白 |
| 3 | `Type` | `file-based`、`content-based` など | 空白 |
| 4 | `Status` | `READY`、`CREATING` など | 空白 |
| 5 | `Database` | 関連するデータベース | 空白 |
| 6 | `Owner` | SDK が返す所有者 | 空白 |

### 7.4 `Description` の取得と BookRAG 判定

- `UI-DATA-001`：`Description` を推測、固定値、または一律の `—` で埋めてはならない。
- 一覧 API が説明を返す場合は、その値を第一候補とする。
- 一覧 API が省略する場合は、最新版 `teradatagenai` の正式な詳細取得 API から補完する。
- 詳細取得は上限付き並列実行とキャッシュを使用し、同じ更新中に逐次取得して待ち時間を増やさない。
- 実際に説明が空の場合、および権限または取得エラーで確認できない場合はセルを空白にする。取得エラーは管理警告で伝える。
- `Description` は取得した文字列を、記号や内部マーカーを含めて改変せず表示する。バッジ、補足文、置換文字列を追加しない。
- BookRAG 対象一覧や Governance の候補は、この意味情報を利用して判定し、名前だけで推測しない。

### 7.5 フィルターと選択

- フィルターは表示済み行に対するローカル処理とし、入力ごとにサーバーへ要求しない。
- 行クリック、`Enter`、または `Space` で選択できる。
- `UI-INTERACTION-001`：選択表示は体感上即時、目標 `100ms` 未満とする。
- `UI-INTERACTION-002`：選択だけでは `VectorStore` を開かず、初期化せず、詳細 API を呼ばず、接続をやり直さない。
- 選択行は背景、左境界、および `aria-selected` で示す。文字色だけに依存しない。
- フィルター後に選択行が非表示になっても、削除対象名を勝手に別の行へ変更しない。

### 7.6 削除

- `Delete selected` は資源選択後かつロールが許可する場合だけ有効にする。
- 削除前に対象名と不可逆操作であることを確認ダイアログへ明示する。
- 送信直前にトップへ処理中メッセージを表示する。対象名は画面上の補助文言ではなく、実際に送信する `vs_name` と一致させ、未選択を `(none)` などの対象名として表示または送信しない。
- 成功時はトップへ成功メッセージを表示し、一覧を最新状態へ更新し、選択を解除する。
- 失敗時はトップへ一件だけエラーを表示し、表、表見出し、列幅、および選択中の対象を維持する。
- 失敗文を選択バーや表上部へ挿入してレイアウトを押し広げてはならない。

## 8. `Vector Store Creation` 詳細設計

### 8.1 目的と表示順

1. `Upload PDF / Documents`
2. `Document Processing Settings`
3. `Content Processing Mode`
4. 選択モード固有の設定
5. Vector Store 名、埋め込み、検索アルゴリズムなどの作成設定
6. 明示的な作成または段階実行ボタン
7. ジョブ進捗と結果

### 8.2 処理モード

利用可能な処理モードは、レジストリから供給される現在のモードだけを表示する。

- `Text PDF Only`：標準的なテキスト文書作成フロー
- `Multi-Format`：Unstructured を使用する複数形式の文書処理
- `Multi-Format BookRAG`：BookRAG テーブルと追跡可能な文書構造を生成する処理

モード切替時は、対象外の入力を非表示にするだけでなく `disabled` にし、送信値へ混入させない。同じ名前の必須入力を複数モードで同時に有効化しない。

### 8.3 入力と説明

- Vector Store 名は必須であり、対象データベース内で意味のある一意名とする。
- 利用者が用途を判断できる説明を保存できることを原則必須とする。
- BookRAG 作成では `unstructured_bookrag_flg` 相当の識別情報を、後で管理一覧から確実に判定できる形で保持する。
- 必須値不足は送信前とサーバー側の両方で検証する。
- ブラウザー標準の検証だけに依存せず、どの項目が不足しているかを明示する。
- `UI-MODEL-001`：Unstructured の provider/model 候補は版管理されたモデルカタログから表示し、provider 選択時は対応する model だけを残す。VLM の空選択は platform default を意味し、文書ページの実行時スクレイピングは行わない。
- `UI-MODEL-002`：Multi-Format と BookRAG の model-backed enrichment は subtype、provider、model を同じカードで選択し、選択値を API へそのまま渡す。two-pass subtype だけは platform-managed model として provider/model を送信しない。
- `UI-MODEL-003`：Coordinates と block extraction は High Res のときだけ有効化する。Generative OCR の自動 block extraction は text element type を含める。

### 8.4 長時間処理

- 文書解析、CSV 生成、テーブルロード、Vector Store 作成は、段階と結果が理解できる形で表示する。
- 二重送信を防止し、実行中ボタンにはスピナーと動詞を含む進捗文を表示する。
- ジョブ進捗は対象パネル内、ジョブ受付・完了・失敗の主要通知はトップへ表示する。
- 再読み込みや再接続後にも必要なジョブ状態を復元できること。
- 単一プロセスの Teradata ランタイム制約を守り、UI 上で不可能な並列実行を期待させない。
- `UI-CREATE-CSV-001`：Generate CSV の送信時に、同一 database と Vector Store 名の load 済み run が見つかった場合は job を作らず、対象名を変更するよう CSV 結果領域へ一件の入力競合エラーを表示する。既存 CSV、table、Vector Store を上書きまたは暗黙再利用しない。

## 9. `Vector Store Retrieval` 詳細設計

### 9.1 表示順

1. 会話または検索結果
2. `Vector Store List` と明示的な一覧更新
3. `Retrieval Method`
4. `Retrieval-only` または `BookRAG API`
5. 質問入力
6. `Send` と `Clear`

### 9.2 Vector Store 選択

- 選択候補は現在の接続に属する Vector Store だけとする。
- 候補がない状態で送信できないようにする。
- 選択そのものでは検索、接続、または初期化を開始しない。
- 一覧更新と選択を同一操作にしない。

### 9.3 検索方式

- `Retrieval-only` では `VectorStore.ask` または `VectorStore.similarity_search` を選択できる。
- `BookRAG API` ではエンドポイントを読み取り専用で示し、`top_k` を許容範囲内で設定する。
- BookRAG を選べない Vector Store に対して BookRAG API を送信する場合は、実行前に理由を明示して防止する。
- 回答とエビデンスは会話領域へ表示し、共通ヘッダーの操作メッセージと混在させない。

## 10. `BookRAG Governance` 詳細設計

### 10.1 タブ

BookRAG Governance は次の 2 タブだけを持つ。

1. `Document Governance`
2. `JSON Inspector`

`Document Governance` の中で、文書メタデータと文書関係を扱う。システム接続設定やユーザー管理をこの領域へ戻してはならない。

### 10.2 Document Governance

- 対象 Vector Store は BookRAG と判定できるものだけを候補にする。
- `UI-GOVERNANCE-001`：`Document Governance` は Vector Store 選択、`Load`、`Refresh Vector Stores` を上部に一組だけ持ち、`Document Metadata` と `Document Relationships` は常に同じ選択中 Vector Store を使用する。
- `Document Metadata` は発行日、精度、シリーズ、役割、論理文書キー、改訂番号、状態を扱う。
- `Document Relationships` は From、Relationship、To、Description、Source、Actions を扱う。
- `Load` は選択中 Vector Store の両領域を同時に読み込み、`Refresh Vector Stores` は候補一覧だけを更新する別操作とする。
- CSV の Import、Export、初期化、保存、更新、削除は権限を明示し、不可逆操作には確認を付ける。
- 一覧またはテーブルが未初期化の場合は、空白ではなく状態と必要な次操作を示す。

### 10.3 JSON Inspector

- 保存済み JSON ファイルを選択し、`Open` で読み込む。
- `Refresh` はファイル候補だけを更新し、暗黙に別ファイルを開かない。
- 内容概要、要素種別、メタデータキー、JSON、Metadata、Text を明確に分ける。
- 大きな JSON は専用スクロール領域へ表示し、ページ全体の横幅を破壊しない。
- ファイルパスは許可された保存領域内のものだけを扱う。

## 11. `System Configuration` 詳細設計

### 11.1 画面構造

`/admin/users` は `System Configuration` という一つの管理画面であり、次の 3 タブへ内容を分ける。

1. `Database Connections`
2. `Unstructured IO`
3. `User Management`

タイトル、説明、`Back to Teradata Vector Store`、3 タブ、選択中タブの内容の順とする。管理画面内に別の `Administration` 見出しを追加しない。

### 11.2 Database Connections

- 左側に保存済み接続一覧、右側に選択中接続の編集フォームを置く。
- 接続を自由に追加、選択、変更、削除できる。
- `Connection name`、`Host`、`Username`、`Database password`、`PAT Token`、`PEM File`、`UES URL`、既定接続を扱う。
- パスワードと PAT は保存後に再表示しない。空欄は既存値維持、明示的な置換だけを受け付ける。
- PEM 内容は暗号化して SQLite に保存する。ブラウザーへ保存パスをシークレット値として露出せず、ファイル名と保存状態だけを示す。
- 一つの接続だけを既定接続にできる。
- 現在使用中の接続を変更または削除する場合は、ランタイム状態との整合を保つ。

### 11.3 Unstructured IO

- 見出しは `Unstructured API`、タブ名は `Unstructured IO` とする。
- `API URL` と `API Key` だけを明確に配置する。
- API キーは暗号化して SQLite に保存し、再表示しない。
- 保存済みの場合は置換方法を説明し、削除は通常保存と混同しない明示的なチェック操作とする。
- チェックボックスと説明文は同じ行または同じラベルブロックにまとめ、巨大な空白を作らない。

### 11.4 User Management

- `Create user` とユーザー一覧を分ける。
- ユーザー一覧の列は `User`、`Role`、`Status`、`Last login`、`Actions` とする。
- ロール変更、有効化・無効化、パスワード再設定を行える。
- 自分自身から最後の管理者権限を失わせる操作など、管理不能になる変更をサーバー側で拒否する。

### 11.5 管理画面のメッセージ

`UI-MESSAGE-001` は管理画面にも適用する。フォーム直上の独自ステータス表示は使用せず、成功・失敗は共通ヘッダーへ一件だけ表示する。入力欄固有の検証理由だけは対象入力の近くへ表示できる。

## 12. 状態モデル

| 状態 | 利用可能な主要操作 | 画面の要件 |
|---|---|---|
| 未設定 | System Configuration を開く | 接続不可の理由を明示 |
| 未接続 | 接続プロファイル選択、Connect | 管理更新、作成、検索、Governance を無効化 |
| 接続中 | 待機 | 二重送信を防止し、短い進捗を表示 |
| 接続済み・未更新 | Refresh、Disconnect | `Refresh to load health and resources` を表示 |
| 更新中 | 待機 | 既存表を不用意に消さず、更新中を示す |
| 更新済み | フィルター、選択、許可された操作 | ヘルス、確認時刻、完全な表見出しを表示 |
| 資源選択済み | Delete selected | 選択はローカルで即時反映 |
| 削除確認中 | Cancel、Delete | 対象名と不可逆性を表示 |
| 削除失敗 | 再試行、更新、別行選択 | トップに一件のエラー、表と選択を維持 |
| 削除成功 | 更新済み一覧を確認 | トップに一件の成功、選択を解除 |

状態遷移のたびに DOM 全体を再構築する必要はない。変更対象を最小限にしつつ、サーバー状態と表示状態が一致することを優先する。

## 13. 表示値と文言

### 13.1 空値の意味

- Vector Store 表で値が返されないセルは空白にする。`—`、`None`、`Not provided` などの代替文字列を入れない。
- 値として文字列や記号が返された場合は、その内容を改変せず表示する。
- `Unavailable`：値そのものではなく、サービスや操作全体が権限、API 応答、または取得失敗により利用できない状態。
- `Not checked` または `Not yet`：まだ操作を実行していない。
- `Unknown`：応答はあるが状態値を解釈できない。

空の表セルを `—` などの占位文字で埋めてはならない。取得失敗を伝える必要がある場合は、セル値ではなく管理警告を使用する。

### 13.2 文言の原則

- UI 本体の表示言語は現在の実装に合わせて英語とする。本書は日本語で仕様を説明する。
- 操作ボタンは `Refresh`、`Save`、`Delete`、`Connect` のように動詞から始める。
- 技術的成功ログだけを表示しない。例として `Database connection established in 318.70 milliseconds. Vector store is initialized.` を選択操作の結果として表示してはならない。
- 成功文は、利用者が何を完了したか理解できる一文にする。
- エラー文は、失敗した対象、原因の要約、次の行動を含める。
- 製品名は `Teradata`、機能名は `Vector Store`、プロジェクト名は技術文脈だけで `teradataevsui` と表記する。

## 14. コンポーネント規則

### 14.1 ボタン

- 主要操作は一つの領域につき原則一つの強調ボタンとする。
- 補助操作は `ghost`、不可逆操作は `danger` 系を使用する。
- 無効状態は見た目だけでなく `disabled` と `aria-disabled` を同期する。
- 実行中はラベル、スピナー、無効状態を同期し、処理終了後に確実に復元する。

### 14.2 タブ

- タブ名は内容の責務を表し、同じ意味の別名を作らない。
- 選択中タブは色だけでなく形状または境界でも判別できるようにする。
- キーボード操作と適切な `role`、`aria-selected`、関連パネル指定を持つことを推奨する。

### 14.3 表

- 見出しには `scope="col"` を使用する。
- 選択可能行にはフォーカスとキーボード操作を提供する。
- 固定見出しの背景は不透明にし、行文字が透けないようにする。
- 列を条件付きで増減する場合は、見出しと全行を同じデータ構造から生成する。

### 14.4 モーダル

- 削除など確認が必要な場合だけ使用する。
- `Escape`、Cancel、背景操作で安全に閉じられる。
- 開いた直後は主要な安全操作または確認操作へフォーカスを移す。
- 閉じた後は起点へフォーカスを戻すことを推奨する。

## 16. アクセシビリティ

- `UI-A11Y-001`：マウスだけでなくキーボードで全主要操作を実行できる。

## 17. 性能と非同期処理

- ローカルのタブ切替、行選択、フィルターはネットワークなしで即時実行する。
- 一覧取得、詳細補完、ヘルス確認は `Refresh management data` に集約する。
- `Description` の詳細補完は上限付き並列実行とリクエスト内キャッシュを使用する。
- 同一画面更新の中で同じ Vector Store の詳細を重複取得しない。
- 処理が `300ms` を超える可能性がある操作は実行中状態を示す。
- 長時間ジョブは HTTP 応答を無期限に保持せず、永続ジョブ状態と進捗表示を利用する。
- タイムアウト、送信失敗、キャンセルを成功と同じ UI 状態遷移の一部として設計する。

## 18. セキュリティとプライバシー

- PAT、パスワード、API キー、PEM 内容を HTML、JavaScript、ログ、エラー、URL、スクリーンショットへ出さない。
- 保存済みシークレットは存在状態だけを表示する。
- すべての状態変更要求に CSRF 対策を適用する。
- ユーザー入力、SDK エラー、ファイル名を HTML として直接挿入しない。
- ファイル選択、Import、JSON 検査は許可された拡張子、サイズ、保存領域を検証する。
- 削除、ロール変更、共有設定変更は監査可能なサーバー操作とする。
- UI 上の非表示や無効化を認可の代わりにしない。

## 20. テスト設計

### 20.1 自動テスト必須項目

- 共通ヘッダーに操作メッセージ領域が一つだけ存在する。
- 同じ成功・失敗メッセージが本文へ重複しない。
- Vector Store 表の見出しが 6 個で、全行のセル数も 6 個である。
- `Description` が取得値と記号を改変せず表示する。
- 説明未登録と取得失敗はいずれも空セルとし、取得失敗だけは管理警告を表示する。
- 行クリックとキーボード選択が HTTP 要求を発生させない。
- 選択後すぐに対象名、行強調、削除ボタン状態が更新される。
- 削除成功で一覧と選択が更新される。
- 削除 `409`、`403`、通信失敗、タイムアウトで表と選択が維持される。
- 未接続時に接続依存操作が無効化される。
- `admin`、`operator`、`viewer` の表示とサーバー認可が一致する。
- System Configuration の 3 タブが正しい内容だけを表示する。
- ユーザー 0 件で初回設定へ誘導し、作成成功、確認不一致、短い password、作成済み再アクセスを検証する。
- シークレットがレスポンス HTML に含まれない。
- `900px`、`1100px`、標準デスクトップ幅で横方向のページあふれがない。

### 20.2 ブラウザー回帰シナリオ

1. 未接続でホームを開き、接続依存メニューが無効であることを確認する。
2. 定義済み接続を選び、選択だけでは通信しないことを確認する。
3. `Connect` を押し、トップに一件だけ結果が表示されることを確認する。
4. `Refresh management data` を押し、ヘルス、確認時刻、6 列の一覧を確認する。
5. 一覧をフィルターし、行をクリックして即時選択を確認する。
6. `Description` の通常値と記号が原文どおり表示され、未登録と取得不能は空セルになり、取得不能時だけ管理警告が出ることを確認する。
7. 削除をキャンセルし、状態が変わらないことを確認する。
8. 削除を成功させ、トップメッセージと一覧更新を確認する。
9. 処理中の Vector Store を削除して `409` を発生させ、トップに一件だけ安全なエラーが出てレイアウトと選択が維持されることを確認する。
10. 作成、検索、BookRAG Governance、System Configuration の主要成功と失敗を一回ずつ確認する。
11. デスクトップ、狭いノート PC、タブレット、モバイル幅のスクリーンショットを比較する。
12. 空のユーザー DB で初回管理者を作成し、入力失敗時の非保存、作成後の setup 閉鎖、通常 login を確認する。

### 20.3 視覚確認項目

- ヘッダーが約 `88px` で、上部に大きな空白がない。
- Teradata ロゴ下が `Enterprise AI Platform` である。
- ナビゲーション名に重複した `Administration` がない。
- 表見出しがスクロール後も見える。
- `Description` 列に意味のある情報がある。
- エラー後もカード、ボタン、表が元の位置にある。
- チェックボックスとラベルが離れていない。
- 主要ボタンが内容に対して不自然に大きくない。
- 空の右側領域や高さだけ大きい空カードがない。

## 21. AI コーディングエージェント用変更手順

### 21.1 変更前

AI エージェントは UI を変更する前に必ず次を実行する。

1. 本書を全文読む。
2. 変更対象のテンプレート、ルーター、ワークフロー、サービス、JavaScript、CSS、テストを検索する。
3. 同じ ID、文言、メッセージ、表、ボタンが他の partial に存在しないか確認する。
4. 表示値の正式なデータ出所を確認し、フィールド名を推測しない。
5. 成功、空状態、権限不足、SDK エラー、通信失敗、狭い画面の各状態を列挙する。
6. 本書のどの規則 ID が影響を受けるか記録する。

### 21.2 変更中

1. 最小のファイル数ではなく、必要な層を漏れなく含む最小の一貫した変更を行う。
2. メッセージは共通トップ経路へ集約する。
3. 選択イベントとサーバー実行イベントを分離する。
4. 表の列は見出しと行を同時に変更する。
5. CSS は成功時だけでなく、長いエラー、空状態、選択状態でも確認する。
6. シークレットや環境固有値をテスト、文書、スクリーンショットへ保存しない。
7. 静的資産を変更した場合はキャッシュ更新方法を確認する。

### 21.3 変更後

1. 関連するユニットテストとブラウザーテストを実行する。
2. 成功経路と失敗経路を実ブラウザーで確認する。
3. メッセージ重複、表見出し、列ずれ、無意味な空白、横あふれを確認する。
4. 操作前後のネットワーク要求を確認し、単なる選択が通信していないことを証明する。
5. 変更した UI のスクリーンショットを複数幅で確認する。ただし環境固有値を公開成果物へ含めない。
6. `git diff` で無関係な変更、生成物、シークレット、個人情報がないことを確認する。
7. 本書と実装が矛盾する場合は、実装だけでなく本書または明示的な差分記録を更新する。

### 21.4 禁止事項

- スクリーンショットだけを見てデータ構造を推測する。
- 列値が分からないため一律に `—` を入れる。
- ローカルメッセージを追加して共通トップメッセージと重複させる。
- 行選択で `VectorStore` を初期化する。
- エラー文を通常レイアウト内へ挿入して列を崩す。
- 表見出しと行を別々に変更する。
- 画面名を理由なく変更し、同義の管理画面を増やす。
- 最新 SDK の確認なしに複数 API 世代を UI に並べる。
- 見た目を整えるためだけに固定高と巨大な空白を追加する。
- テストを通すために重要情報を非表示にする。
- ユーザーの既存変更を巻き戻す。

## 22. 完了条件

UI 変更は、次の全項目を満たした場合だけ完了とする。

- [ ] 画面の目的と主要操作が一目で分かる。
- [ ] 同じ機能名または管理導線が重複していない。
- [ ] 操作メッセージがトップに一件だけ表示される。
- [ ] 成功、失敗、空状態、未接続、権限不足でレイアウトが安定している。
- [ ] 表の見出し、列数、データ、空値の意味が正しい。
